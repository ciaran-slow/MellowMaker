### Named Android scenario for #16

`FlatList` defaults `removeClippedSubviews` to `true` on Android
(`node_modules/react-native/Libraries/Lists/FlatList.js`). The
`ListHeaderComponent` cell is a direct child of the scroll content, and after
#56 that cell holds the title, progress row, and the counter card.

**Run this on Android during the #16 device pass:** open a pattern with six or
more steps, scroll until the counter card leaves the viewport entirely, then
scroll back to the top. **Expect:** the header is still there, the counter still
shows its saved value, and its label is unchanged.

Unlike #43's guide header this one holds **no WebView**, so a detach would be
cosmetic rather than a torn-down media session — which is why it is recorded as
a scenario to run rather than a `removeClippedSubviews={false}` prop change to
make. Nobody has seen it fail; it was derived from the React Native default, not
observed. iOS is unaffected (the default is `false` there).
