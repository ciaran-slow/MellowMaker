## Why there is no Maestro leg

Maestro cannot drive VoiceOver or TalkBack (architecture §14), so the only thing
a flow could assert about a repeated rejection is that the same error text is
**still visible** — which passes identically under the exact bug this issue
fixes, because the text was never removed in the first place. That is the
vacuous-assertion trap in `smoke-verification.md` §4, and a vacuous leg is worse
than none because it is counted as evidence. No `.maestro` file is edited by this
PR.

This machine additionally has no JDK, no Android SDK and no simulator runtime, so
no `test:smoke:*` script can run at all regardless.

## Still on-device-unverified

**The utterances themselves, on both platforms.** Jest can prove the iOS
announcer was called and that Android's alert identity advanced; it cannot prove
VoiceOver spoke, that TalkBack spoke the remounted live region, or that neither
platform spoke twice. Specifically provisional:

- AC1 "A second identical rejection on the paste field produces an observable
  change" — the announcement call is pinned; the **utterance** is not.
- AC2 "a re-render that the maker did not cause … still announces nothing" — the
  zero-call and unchanged-identity assertions are pinned; screen-reader silence
  is not.
- AC4 "Android's live region and iOS's `announceForAccessibility` must agree on
  the repeat, not diverge" — the platform gate is pinned in Jest; **whether
  TalkBack actually re-speaks a remounted `accessibilityLiveRegion`** is the one
  genuinely unverified mechanism in this change. Plan §7 D5 records the fallback
  if #16 finds it silent: add an explicit Android announce behind the same
  `attemptChanged` condition, a three-line change inside `useAnnouncement` with
  no surface touched.

### Owner-run script (iPhone via `npx expo start`, then an Android target at #16)

1. iPhone + VoiceOver on. Guides → a guide → **Edit guide** → paste a
   chapter-free paragraph into the paste field → **Review pasted steps** → hear
   the rejection.
2. Tap **Review pasted steps** again, changing nothing. Expect the rejection
   spoken a **second** time. Confirm the VoiceOver cursor does not jump away from
   where it was — a remounted `Text` could in principle move it, and that is the
   one residual risk this design carries.
3. Repeat with a *different* chapter-free paragraph pasted in between. Same
   rejection, spoken again.
4. Leave the error showing and type into the guide's **Title** field. Expect
   **silence** — the negative branch.
5. The same four steps against **Add step** with the instruction left blank.
6. Android + TalkBack: all of the above, and specifically that step 2 speaks
   **once**, not twice — the check that the live-region remount and the iOS
   announcer have not both fired.
